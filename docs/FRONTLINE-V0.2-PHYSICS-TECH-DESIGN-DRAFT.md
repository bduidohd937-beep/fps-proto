# PROJECT DUEL — FRONTLINE V0.2
## 기술설계 4차: 3D Physics Core / 성능 최적화
**상태: DRAFT / 검토용 (구현·정식 확정 아님)**  
**우선 전투 방향:** B — 경쾌한 이동 + 무게감 있는 총기 + 사실적인 전장  
**현재 기준:** V0.1.2, `feat/online-fps-mvp-v0.1`, Render 라이브 버전은 그대로 유지

### 1. 설계 목표와 비목표
**목표:** 기존 1대1 방 생성·초대·사격·승패를 보존하면서 서버 권한 기반 3D 좌표, 점프, 낙하, 착지, 경사면, 계단, 입체 충돌, 서버-클라이언트 위치 보정 가능 구조 마련.

**이번 V0.2.0에서 제외:** 총기 상점, 신규 총기, 고급 3D 에셋, 4대4, 영구 계정·지갑, 앉기/ADS의 완성 구현(후속 패치). 실험적 3D 물리를 검증 전 Render 공개 서비스에 배포하지 않는다.

### 2. 현재 코드의 실제 이행 포인트
- `shared/rules.js`: `movePlayer()`는 `{x,z}`만 이동. `shotHitsPlayer()`의 시선 높이 `PLAYER_EYE=1.55` 고정.
- `server/index.js`: 30Hz 타이머 및 2틱마다 상태 전송(~15Hz). 입력은 `forward/strafe/sprint/yaw/pitch`이며 위치값은 받지 않음.
- `src/components/GameScene.jsx`: 클라이언트에서 동일한 평면 `movePlayer`로 예측하고 서버 좌표에 보정.
- `src/App.jsx`: 방 생성/게임 UI 및 WebSocket 연결, 전투 상태 매 스냅샷 수신.

### 3. 공통 좌표 규칙
- 오른손 좌표계, **+Y가 위쪽**, XZ가 지면. 단위 1은 1m.
- `position=(x,y,z)`: **발바닥 기준**; 지면에서 `y=0`, 2층 발판에서 `y≈2.8`.
- 히트박스/카메라는 캐릭터 `position.y`를 기준으로 상대 높이를 계산.
- 캡슐 플레이어(임시): 서 있을 때 총 높이 1.8m, 반경 0.44m, 눈 높이 +1.55m. 캡슐 강체 중심은 발보다 +0.9m, cylinder half-height 0.46m.
- Render 모델(mesh), collision 모델(collider), 히트박스(head/body)를 구분하고 이동·전투의 충돌 모델은 일치시키되 렌더 에셋에 종속되지 않게 유지.

### 4. 물리 파라미터 후보 (미확정)
| 항목 | 검토 시작값 | 확인 조건 |

### 5. 물리 루프 (서버 권한)
Rapier 3D JavaScript Kinematic Character Controller를 **후보**로 선택한다. 메인 서버가 `world`, collider, 입력 큐를 소유한다.
- 고정 tick: 30Hz. physics 60Hz 서브스텝은 **필요한 경우에만** 1대1 성능 측정 후 도입한다.
- 1) 입력 패킷 순서/범위/행동 에지 검증.
- 2) 수평 조작(전력질주·공중 제어 포함)을 목표 이동 벡터로 변환.
- 3) `verticalVelocity -= gravity * fixedDelta` 로 중력 적분. 지면 착지 시 음수 수직 속도 제거.
- 4) 지면에서만 점프 에지를 소비. `verticalVelocity = sqrt(2*g*jumpHeight)`. 공중 재점프 금지.
- 5) `characterController.computeColliderMovement(collider, desiredTranslation)`으로 장애물/경사/계단 수정 이동 계산.
- 6) `computedMovement()` 결과를 키네마틱 강체의 다음 위치에 적용. 지면 판단은 실제 충돌/접지 판정으로 갱신.
- 7) `world.step()` 및 스냅샷 전송. 반올림/상한과 센서 충돌 그룹은 별도 검증.
- 캐릭터 회전(Yaw/Pitch)은 입력 검증 후 별도로 유지. Rapier Character Controller는 이동(Translation) 계산 담당.

클라이언트는 비슷한 입력 예측을 실행하되 *정답은 항상 서버 좌표*. 오차가 커지면 스냅, 작으면 부드럽게 보정한다. 서버·클라이언트 물리 결과가 비트 단위로 같을 거라고 가정하지 않는다.

### 6. 입력과 상태 패킷 초안
```js
// Client -> Server. server ignores attempted position/hp/damage fields.
{
  type: 'player:input-v2',
  seq: 1203,               // monotonically increasing integer
  moveX: 1, moveZ: 0,      // [-1, 1], normalized diagonals
  yaw: -0.12, pitch: 0.10, // finite radian
  sprint: true,
  jumpId: 8                // rising-edge ID; replay until acknowledged
}
// Server -> Client
{
  type: 'match:state-v2',
  serverTick: 902,
  ackSeq: 1203,
  ackJumpId: 8,
  players: [{
    id: '...',
    position: {x: 0,y: 2.8,z: 5},
    velocity: {x: 0,y: 0,z: 0},
    grounded: true,
    stance: 'stand',
    yaw: 0, pitch: 0,
    hp: 100
  }]
}
```
- 점프 `jumpId`는 ACK될 때까지 재전송할 수 있으며, 서버는 이미 처리한 ID를 재적용하지 않는다.
- 단순 위치 스냅샷은 유실 허용 가능; 점프·사망·승패·무기 구매 등 중요 이벤트는 **ACK/중복 방지** 필요.
- 입력 시각·`dt`를 클라이언트가 조작해 빠르게 이동하는 방식은 허용하지 않는다. 서버가 고정 delta 사용.
- 미응답 상태에서 구 버전 프로토콜과 혼용하지 않는다. V2 패킷 전환은 별도 점진 이관한다.

### 7. 클라이언트 예측 및 보정
- 로컬 플레이어: 입력 `seq`를 보관하고 렌더 중 즉시 예측.
- 서버 `ackSeq` 도착 시 해당 상태를 기준으로 ACK 이후 입력만 재적용.
- 예측 오차 0.10m 이하: 표시상 보간. 0.10~0.5m: 짧은 시간 부드럽게 보정. 0.5m 초과 또는 스폰/사망: 즉시 재동기화(초안 수치).
- 상대 플레이어: 버퍼링된 서버 스냅샷 사이 보간; 위치가 크게 바뀌는 리스폰은 즉시 스냅. 화면 보간이 서버 명중 판정을 대체하지 않도록 한다.
- 브라우저 비활성 상태나 네트워크 지연 복귀 시 길게 누른 키/점프 상태가 남지 않도록 초기화.

### 8. 맵 충돌용 Graybox
- 첫 이관은 현 기존 맵의 블록을 충돌체로 옮겨서 검증하며, IRON DEPOT 완성 모델은 후속 V0.2.2.
- `mapColliders[]`는 바닥·벽·엄폐물·계단·2층 발판 구분 ID 사용.
- 시각 Mesh와 충돌 collider를 분리하고, 서버에는 **렌더 에셋 없이 충돌 데이터만** 적재한다.
- 스폰은 `(x,y,z,yaw)`로 확장하고 발밑 지면과 상부 공간이 비어 있는지 검사한다.

### 10. 합격 테스트: 구현 전 약속
- [ ] 지면 점프 높이와 착지 시간 오차를 정상 범위 내 측정.
- [ ] 공중 중복 점프 없음; 입력 지연 시 점프 에지 중복 처리 없음.
- [ ] 플레이어 캡슐이 벽, 2층 바닥, 난간을 관통하지 않음.
- [ ] 상자 위 착지/계단 오르기/난간 아래 떨어짐 정상 동작.
- [ ] 공중에서 사격할 때 플레이어 모델과 히트박스 높이 일치.
- [ ] 2개 브라우저에서 점프·리스폰·승패 동기화 유지.
- [ ] 패킷 지연/유실 시 입력 큐가 제한되고 수치가 발산하지 않음.
- [ ] Render 무료 인스턴스에서 1대1 전투 메모리/CPU/지연 실제 측정.
- [ ] 기존 전장 생성·초대·5킬·재대전·재장전 회귀 테스트.
- [ ] 1080p 기준 목표 60FPS/일관된 프레임타임을 검토하되 실제 대상 PC 측정 전 성능 개선을 단정하지 않음.
