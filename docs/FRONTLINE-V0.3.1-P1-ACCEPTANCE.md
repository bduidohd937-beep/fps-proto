## 자세·카메라·이동 측정

실제 Chromium 입력과 서버 상태를 함께 읽어 측정했다. 카메라 눈높이 기준은 standing 1.55m, crouch 0.96m, prone 0.42m이다.

| 상태 | 서버 속도 | 카메라 눈높이 | 서버 눈높이 | 위치 오차 |
|---|---:|---:|---:|---:|
| 걷기 | 4.92 m/s | 1.527 m | 1.550 m | 0.246 m |
| 전력질주 | 6.66 m/s | 1.548 m | 1.550 m | 0.340 m |
| 앉기 | 3.48 m/s | 0.975 m | 0.960 m | 0.044 m |
| 엎드리기 | 1.30 m/s | 0.425 m | 0.420 m | 0.011 m |

브라우저 수락 테스트는 모두 기준 범위 안에서 통과했다. 기존 서버 단위·통합 테스트도 낮은 배관, 천장, 벽, 계단, 점프 및 자세 전환 충돌을 통과했다.

## 예측 보정·리스폰 복구

정상적인 서버 스냅샷과 클라이언트 예측의 위치 오차 수렴은 위 브라우저 측정으로 확인했고, 기존 대규모 보정 분기 및 리스폰 시 정확한 로컬 위치 리셋 코드를 검토했다. 기존 reconnect/respawn E2E도 통과했다.

다만 네트워크 패킷을 의도적으로 지연·변조해 큰 위치 불일치를 강제하는 테스트 장비는 이번 검증에 포함하지 않았다. 따라서 강제 불일치 복구는 완전 수락이 아니라 잔여 위험이다.

## 반동·탄착

기존 88개 서버/도메인 테스트 중 무기 4종 각각 20발, 자세별 탄퍼짐, 연사 인덱스, 일시정지 후 초기화, 재장전·무기 변경·리스폰 회귀가 통과했다. 서버 반동 패턴과 클라이언트 시각 반동 코드는 일관된 방향으로 확인했다.

프레임 캡처 기반의 서버 발사 방향과 화면 반동 수치의 직접 오차 측정은 수행하지 못했으므로, 이 항목도 정량적 완전 수락보다는 회귀 통과로 기록한다.

## 테스트 결과

- `npm run check`: 통과 — 88 tests, build 성공
- `npx playwright test e2e/acceptance.spec.js`: 통과
- `npm run test:e2e`: 통과 — 11 tests
- 실제 Socket.IO 사망→리스폰→5킬 종료→재대전: 통과
- 친구 대전 기본 반복 2회: 2/2 통과
- 친구 대전 스트레스 반복 10회: 7/10 통과, 3회 입장 흐름 45초 timeout

실패한 스트레스 반복은 상대 브라우저가 전투 화면에 진입하지 못하고 호스트가 “상대가 나갔습니다” 대기 상태에 남은 현상이다. 단순 재시도나 timeout 증가로 가리지 않았다. 기본 단독 반복은 통과했으므로 재현 빈도가 있는 온라인 초기화/브라우저 부하 경로로 남긴다.
